# 当前问题清单（后端/服务端）

更新时间：2026-04-22

## 高危问题

- 未鉴权 + 任意工具执行：HTTP 暴露 `POST /api/v1/tools/execute`，执行链路缺少认证与授权拦截，`execute_tool()` 直连 `registry.call()`。
- CORS 过宽 + 无身份边界：`allow_origins=["*"]` 且接口普遍未鉴权，存在浏览器侧跨站调用本地服务风险。
- WebSocket 全局事件泄漏：连接默认订阅全局事件总线，未做连接/会话过滤，可能看到其他会话事件与权限请求参数。

## 中危与设计冗余

- 全局 runtime 并发竞争：`send_message/switch_session` 并发修改共享 runtime 状态，存在串会话和上下文污染风险。
- 全局 APIService 单例耦合：`get_global_api_service()` 采用全局单例，不适合多用户并发隔离。
- transcript logger 切会话不一致：runtime 切换 transcript 后，logger 绑定关系未同步重建，存在归档错位风险。
- 未使用状态字段：`active_queries` 当前未参与取消、限流和调度，属于维护噪音。

## 结论

- 目前存在可被利用的严重风险，优先级应定为 P0。
- 架构层存在明显技术债，尤其是全局可变状态和事件隔离不足。

## 修复优先级

- P0：补齐 HTTP/WS 认证授权；高风险工具默认拒绝未认证调用。
- P0：事件按 `connection_id/session_id` 隔离，禁止全局敏感广播。
- P1：runtime/service 按用户或连接隔离；最小方案先加串行锁和上下文隔离。
- P1：修复 transcript logger 与 session switch 的绑定一致性。
- P2：清理 `active_queries` 等冗余状态与死字段。
