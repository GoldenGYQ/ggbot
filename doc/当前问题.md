# 当前问题清单（后端/服务端）

更新时间：2026-04-24

## 高危问题

- [未解决] 未鉴权 + 任意工具执行：HTTP 暴露 `POST /api/v1/tools/execute`，执行链路仍缺少认证与授权拦截，`execute_tool()` 仍可直连 `registry.call()`。
- [未解决] CORS 过宽 + 无身份边界：`allow_origins=["*"]` 且接口普遍未鉴权，仍存在浏览器侧跨站调用本地服务风险。
- [已解决] WebSocket 全局事件泄漏：`send_message` 实时事件已改为绑定发起连接并定向回发（按 `connection_id` 投递），不再全连接广播。

## 中危与设计冗余

- [部分缓解] 全局 runtime 并发竞争：API 已引入会话级执行上下文与会话锁（`SessionRuntimeManager` + per-session lock），串会话风险明显下降。
- [未解决] 全局 APIService 单例耦合：`get_global_api_service()` 全局单例仍在，不适合多用户并发隔离。
- [已解决/项失效] transcript logger 切会话不一致：legacy `transcript_logger` 已移除，当前主链路不再依赖该绑定关系。
- [未解决] 未使用状态字段：`active_queries` 仍未参与取消、限流和调度，属于维护噪音。

## 结论

- 仍存在可被利用的 P0 风险（主要集中在认证授权与 CORS 边界）。
- 事件隔离已完成关键修复，但服务实例边界与安全治理仍有技术债。

## 修复优先级

- P0：补齐 HTTP/WS 认证授权；高风险工具默认拒绝未认证调用。
- P0（已完成）：事件按 `connection_id/session_id` 隔离，禁止全局敏感广播。
- P1（部分完成）：runtime/service 按用户或连接隔离；最小方案会话锁与上下文隔离已落地。
- P1（已完成/关闭）：修复 transcript logger 与 session switch 的绑定一致性（随 legacy logger 移除关闭）。
- P2：清理 `active_queries` 等冗余状态与死字段。
